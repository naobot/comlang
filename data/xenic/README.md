# xenic data

One project's own material, kept out of `supabase/` and `src/` so that neither reads as
generic. The tooling that produces and consumes it lives in `scripts/xenic/`.

| | |
|---|---|
| `seed/lexicon.json` | Generated from the harness's `grammar.yaml` by `pnpm xenic:import-lexicon`. Loaded into `lexicon_entries` by hand. |
| `seed/word-classes.json` | Generated by `pnpm xenic:import-word-classes`; fed to the `save_word_classes` RPC. |
| `seed/morphology.json` | Hand-authored. The `project_morphology.spec` document — the affixes, slot order, phonological rules and entry-key conventions the app reads instead of hard-coding them. **Must not drift from the live row.** |
| `exports/xenic-<date>/` | A frozen snapshot: `raw/` is the out-of-band dump it was built from, the `xenic-*.yaml`/`.csv` beside it are what `pnpm xenic:export-snapshot` derives for the harness. |

The export filenames are a contract with the harness — do not rename them. `data/**` is
excluded from the formatter (`vite.config.ts`) so a committed snapshot keeps the exact
bytes it was handed over as.
